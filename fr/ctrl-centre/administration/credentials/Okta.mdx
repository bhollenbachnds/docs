<Warning>
  Cet article nécessite que vous disposiez au moins de la version PADS4 2025.2.
</Warning>

PADS4 permet l'intégration avec **Okta** pour simplifier **l'authentification et la gestion des utilisateurs**. Cela s'effectue via l'interface **Credentials** dans **PADS4 CTRL Center**.

Suivez les étapes ci-dessous pour connecter votre instance Okta :

## 1. Accéder au PADS4 CTRL Center

Pour commencer :

* Ouvrez votre **navigateur web**.
* Accédez à l'**URL du serveur PADS4** (soit un nom DNS, soit une adresse IP).
* Connectez-vous avec un **compte Administrateur**.

Une fois connecté :

* Cliquez sur **Home**.
* Utilisez le bouton **Toggle Sidebar** situé en **haut à gauche** de l'écran.
* Accédez à **Credentials**.
* Puis sélectionnez **Providers**.

## 2. Créer l'application Okta

Pour configurer un fournisseur d'identité Okta, connectez-vous à Okta en tant qu'Administrateur et créez une nouvelle intégration d'application Okta.

* Sur Okta, accédez à la page Applications.
* Cliquez sur "Create App Integration".

![Okta App1](/images/ctrl-centre/administration/credentials/Okta-app1.png)

* Sélectionnez la méthode de connexion "SAML 2.0" et cliquez sur "Next".

![Okta App2](/images/ctrl-centre/administration/credentials/Okta-app2.png)

* Remplissez les informations demandées dans le formulaire et cliquez sur "Next".

![Okta App3](/images/ctrl-centre/administration/credentials/Okta-app3.png)

Par exemple :

* Name: PADS4

## 3. Configurer SAML 2.0

* Modifiez la configuration des paramètres SAML.

![Okta App4](/images/ctrl-centre/administration/credentials/Okta-app4.png)

<Note>
  Assurez-vous que les valeurs "Single sign-on URL" et "Audience URI (SP Entity ID)" ont la structure décrite ci-dessous, sinon la configuration ne fonctionnera pas.
</Note>

* Single sign-on URL :
  * URL PADS4 locale avec **/rdx/**[**nds.services**](http://nds.services)**.authentication.integration/api/v1/pads/Saml2/Acs**
  * Par exemple : [https://pads4.mycompany.com/rdx/nds.services.authentication.integration/api/v1/pads/Saml2/Acs](https://pads4.mycompany.com/rdx/nds.services.authentication.integration/api/v1/pads/Saml2/Acs)
* Audience URI (SP Entity ID) :
  * URL PADS4 locale avec **/saml** 
  * Par exemple : [https://pads4.mycompany.com/saml](https://pads4.mycompany.com/saml)

<Warning>
  Si le domaine de votre instance PADS4 est différent de "pads", vous devez mettre à jour le domaine avec votre propre nom de domaine. Par exemple, pour un domaine nommé "domainone", l'URL sera [https://pads4.mycompany.com/rdx/nds.services.authentication.integration/api/v1/domainone/Saml2/Acs](https://pads4.mycompany.com/rdx/nds.services.authentication.integration/api/v1/domainone/Saml2/Acs).

  Votre nom de domaine configuré peut être vérifié en vous connectant avec votre compte su\root et en accédant à la section "Domains" :

  ![Domain Config](/images/ctrl-centre/administration/credentials/Domain-config.png)
</Warning>

## 4. Attributs et revendications

* Modifiez les attributs et les revendications pour qu'ils correspondent aux valeurs ci-dessous.

| Nom                                                                                                                                      | Format du nom | Valeur         |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ------------- | -------------- |
| [http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress) | Unspecified   | user.email     |
| [http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname)       | Unspecified   | user.firstName |
| [http://schemas.xmlsoap.org/ws/2005/05/identity/claims/surname](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/surname)           | Unspecified   | user.lastName  |

![Okta App5](/images/ctrl-centre/administration/credentials/Okta-app5.png)

* Pour l'attribut de groupe, suivez la configuration ci-dessous et assurez-vous que le filtre est défini sur l'option **"Matches regex"**.

| Nom                                                                                | Format du nom | Filtre        | Valeur |
| ---------------------------------------------------------------------------------- | ------------- | ------------- | ------ |
| [http://schemas.xmlsoap.org/claims/group](http://schemas.xmlsoap.org/claims/group) | Unspecified   | Matches regex | (\*?)  |

![Okta App6](/images/ctrl-centre/administration/credentials/Okta-app6.png)

* Cliquez sur le bouton "Next".
* Cliquez sur le bouton "Finish" pour créer l'intégration de l'application.

## 5. Attribuer des groupes d'utilisateurs à l'application

Pour définir quels groupes d'utilisateurs ont accès à l'application, attribuez les groupes d'utilisateurs souhaités à l'application.

* Sur l'application que vous venez de créer, sélectionnez l'élément "Assignments" dans le menu supérieur.
* Cliquez sur le bouton "Assign" puis sur "Assign to groups".

![Okta App7](/images/ctrl-centre/administration/credentials/Okta-app7.png)

* Cliquez sur "Assign" pour les groupes que vous souhaitez attribuer à l'application et cliquez sur "Done".

![Okta App8](/images/ctrl-centre/administration/credentials/Okta-app8.png)

## 6. Collecter les données de configuration nécessaires à la création du fournisseur d'identité dans PADS4

Pour créer le fournisseur d'identité dans PADS4, collectez certaines informations auprès de votre fournisseur d'identité Okta nouvellement créé. Vous aurez besoin de ces informations pour configurer le fournisseur dans PADS4.

Cliquez sur l'onglet "Sign On" de votre application créée et suivez les instructions ci-dessous :

* Accédez à l'onglet "Sign On".
* Sur le panneau SAML 2.0, cliquez sur le bouton "More details".
* Collectez les informations suivantes :

| Info. requise       | Exemple                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Metadata URL        | [https://myokta.okta.com/app/xxxxxxxxxxxx/sso/saml/metadata](https://myokta.okta.com/app/xxxxxxxxxxxx/sso/saml/metadata) |
| Sign on URL         | [https://myokta.okta.com/app/xxxxxxx/xxxxxxxxxxxx/sso/saml](https://myokta.okta.com/app/xxxxxxx/xxxxxxxxxxxx/sso/saml)   |
| Signing certificate | okta.cert                                                                                                                |

## 7. Configurer le fournisseur dans PADS4

Avec les informations configurées et récupérées ci-dessus, vous pouvez configurer l'intégration Okta dans PADS4.

* Connectez-vous au portail web PADS4 de votre instance PADS4 avec un compte disposant au moins de la licence PADS4 System Management.
* Sur le tableau de bord, ouvrez le menu de gauche et accédez à "Credentials" en bas à gauche.
* Cliquez sur "Providers" puis sur "New".

![Credentials Okta](/images/ctrl-centre/administration/credentials/Credentials-okta.png)

* Ouvrez le menu de configuration Okta.

![Okta Provider Details](/images/ctrl-centre/administration/credentials/okta-provider-details.png)

Remplissez les informations comme suit :

* Name: The name of your provider in PADS4 (can be any value)
* Identifier: The "**Issuer**" collectée à l'étape 6.
* Reply URL : Votre FQDN PADS4 local
  * Example: [**https://pads4.mycompany.com**](https://pads4.mycompany.com)
* Metadata URL : La "**Metadata URL**" collectée à l'étape 6.
* **Identifier** et **Assertion Consumer Service URL** seront remplis automatiquement.

Passez à l'étape 2 pour télécharger les certificats requis :

![Okta Certificate](/images/ctrl-centre/administration/credentials/okta-certificate.png)

* **Provider signing certificate** : Téléchargez le certificat de signature Okta récupéré à l'étape 6.
* **Certificate from/for "domainone"** : Téléchargez tout certificat (.PFX) que vous souhaitez utiliser pour signer les assertions de PADS4 vers le fournisseur d'identité externe.
* **Private key password** : Saisissez le mot de passe associé au certificat PFX utilisé ci-dessus.

<Tip>
  Si vous n'avez pas besoin d'activer le provisionnement SCIM sur la configuration de votre fournisseur d'identité, terminez le processus de création du fournisseur d'identité en cliquant sur le bouton "Create".
</Tip>
