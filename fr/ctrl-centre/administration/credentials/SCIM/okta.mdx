- title: SCIM pour Okta
- description: Configurez le provisionnement des utilisateurs SCIM entre Okta et
    PADS4 pour créer, mettre à jour et désactiver automatiquement les
    utilisateurs et les groupes via l'application Okta.
---

Le provisionnement des utilisateurs est le processus de création, de mise à jour et de suppression automatiques des comptes utilisateurs. Il garantit que les utilisateurs obtiennent le bon accès lorsqu'ils rejoignent l'organisation, changent de rôle ou la quittent.

Pour activer le provisionnement des utilisateurs, PADS4 utilise le standard SCIM (System for Cross-domain Identity Management). SCIM fournit un moyen cohérent et automatisé de créer, mettre à jour et désactiver des utilisateurs.

Pour configurer le provisionnement des utilisateurs, créez un fournisseur d'identité en suivant les instructions de configuration SSO dans ce document. Activez ensuite l'option SCIM sur celui-ci et configurez la configuration SCIM sur le fournisseur d'identité externe.

## 1. Activer SCIM sur le fournisseur d'identité PADS4

Pendant que vous configurez votre fournisseur d'identité PADS4, vous pouvez activer l'option SCIM Provisioning.

Pour l'activer lors de la création du fournisseur d'identité :

* Cliquez sur l'étape « SCIM Provisioning »
* Cliquez sur « Enable SCIM Provisioning »

<Frame>
  ![Okta Provider](/images/CTRL-Center/Credentials/Providers/Okta/OktaProvider.png)
</Frame>

Après l'avoir activé, conservez les données suivantes :

* SCIM URL
* SCIM Access Token

Vous réutiliserez ces valeurs ultérieurement lorsque vous configurerez le SCIM Provisioning sur le fournisseur d'identité externe.

Sur Okta, vous pouvez activer la fonctionnalité de provisionnement des utilisateurs sur la même application que vous avez précédemment créée pour le SSO.

#### Créer la configuration de provisionnement

* Ouvrez l'application que vous avez précédemment créée pour la configuration SSO

![Scim Okta1](/images/ctrl-centre/administration/credentials/SCIM/scim-okta1.png)

* Cliquez sur l'onglet « General », puis cliquez sur le bouton « Edit » dans le panneau « App settings »
* Cochez l'option « SCIM » dans le champ « Provisioning »
* Cliquez sur « Save »

![Scim Okta2](/images/ctrl-centre/administration/credentials/SCIM/scim-okta2.png)

Après avoir enregistré l'option, un nouvel onglet « **Provisioning** » apparaît en haut.

* Cliquez sur l'onglet « **Provisioning** »
* Cliquez sur le bouton « **Edit** » et saisissez les informations suivantes :
  * SCIM Connector URL – Entrez l'URL affichée sur le fournisseur d'identité PADS4 sous « SCIM URL » (ex. `https://pads4.mycompany.com/rdx/nds.services.user.scim/api/v1/scim`)
  * Unique identifier field for users – Définit l'identifiant unique qu'Okta et PADS4 utilisent comme référence commune. **La valeur par défaut est « username »**
  * Supported provisioning actions – Sélectionnez les actions suivantes
    * Push new users
    * Push profile updates
    * Push groups
  * Authentication Mode – Sélectionnez « **HTTP Header** »
  * HTTP Header
    * Authorization – Entrez le jeton affiché sur le fournisseur d'identité PADS4 sous « SCIM Access token »

<Warning>
  Attention: This SCIM Connector URL must be publicly accessible because Okta uses it as a callback for user provisioning.
</Warning>

* Cliquez sur « Test Connector Configuration » pour vérifier que la configuration est correcte

![Scim Okta3](/images/ctrl-centre/administration/credentials/SCIM/scim-okta3.png)

* Si le test est réussi, cliquez sur le bouton « **Save** » pour appliquer cette configuration

![Scim Okta4](/images/ctrl-centre/administration/credentials/SCIM/scim-okta4.png)

Après avoir enregistré la configuration de l'intégration, de nouveaux onglets apparaissent à gauche.

* Cliquez sur l'onglet « **To App** », puis cliquez sur le bouton « Edit » dans la section « **Provisioning to App** »
* Cochez les cases « **Enable** » pour les sections suivantes :
  * Create users
  * Update user attributes
  * Deactivate users
* Cliquez sur le bouton « **Save** » pour appliquer les modifications

![Scim Okta5](/images/ctrl-centre/administration/credentials/SCIM/scim-okta5.png)

#### Configurer le mappage des utilisateurs et des groupes

Okta configure le mappage des utilisateurs et des groupes par défaut lors de la création de l'application. Assurez-vous qu'au moins les attributs suivants sont mappés sur votre application :

![Scim Okta6](/images/ctrl-centre/administration/credentials/SCIM/scim-okta6.png)

* **(Facultatif)** Ajouter des attributs facultatifs

Vous pouvez également ajouter des attributs facultatifs définis par PADS4.

Pour les utiliser, cliquez à nouveau sur « Add New Mapping » pour chaque attribut et configurez-le.

Actuellement, les attributs facultatifs disponibles sont :

| **Attribut cible** | **Commentaire**                                                              |
| :----------------- | :--------------------------------------------------------------------------- |
| nfc                | Synchronise toute valeur saisie dans la propriété NFC de l'utilisateur PADS4 |

#### Attribuer le groupe autorisé à accéder à l'application

Sur Okta, définissez quels membres du groupe se synchronisent avec l'application.

Vous configurez cela de la même manière que la configuration de l'authentification unique (SSO). Les groupes d'utilisateurs que vous avez déjà définis pour le SSO s'appliquent automatiquement à cette configuration.

Pour étendre cette liste de groupes d'utilisateurs, suivez les instructions dans la section **Assign user groups to the application** de l'article SSO correspondant.
