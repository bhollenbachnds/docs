- title: Configurer le plugin CMS Calendar avec Azure
- description: Configurez le plugin CMS Calendar de PADS4 avec Microsoft Entra ID
    et Exchange 365 via OAuth 2.0 afin que Workspace puisse lire et réserver des
    salles.
---

Configurez votre environnement Microsoft Azure / Exchange pour configurer le plugin CMS Calendar et permettre les réservations de salles via Workspace.

<Note>
  Microsoft a renommé Azure Active Directory en Microsoft Entra ID.
</Note>

Lors de l'authentification avec le nouveau paramètre OAuth 2.0 dans Exchange 365 (Azure), vous avez besoin d'un type différent de vérification de compte.

Ajoutez l'application PADS4 CMS/Workspace dans Microsoft Entra ID et ajoutez un compte de service.

Suivez les étapes ci-dessous pour configurer votre environnement Microsoft Entra ID pour une utilisation avec PADS4.

## Enregistrer l'application

1. Ouvrez un navigateur, accédez au centre d'administration Microsoft Entra ID et connectez-vous à l'aide d'un **compte personnel** (alias : Microsoft Account) ou **Compte professionnel ou scolaire**.
2. Sélectionnez **Identity** dans la navigation de gauche, puis sélectionnez **App registrations** sous **Applications**.

   ![Image38 Pn](/images/Image38.png)
3. Sélectionnez **New registration**. Sur la page **Register an application**, définissez les valeurs comme suit.

   **a.** Définissez **Name** sur un nom convivial pour votre application.

   **b.** Définissez **Supported account types** sur le choix qui correspond à votre scénario.

   **c.** Pour **Redirect URI**, changez le menu déroulant en **Public client (mobile & desktop)** et définissez la valeur sur :

   <CodeGroup>
     ```filename
     urn:ietf:wg:oauth:2.0:oob
     ```
   </CodeGroup>

   ![Image39 Pn](/images/Image39.png)
4. Sélectionnez **Register**. Sur la page suivante, copiez les valeurs de **Application (client) ID** et **Directory (tenant) ID** et enregistrez-les. Vous en aurez besoin plus tard pour configurer le plugin de calendrier dans CMS.

## Configurer pour l'authentification d'application uniquement

Pour utiliser les permissions d'application, suivez ces étapes supplémentaires.

1. Sélectionnez **Manifest** dans la navigation de gauche sous **Manage**.
2. Localisez la propriété **requiredResourceAccess** dans le manifeste et ajoutez ce qui suit à l'intérieur des crochets (\[]) :

   ```
   {
     "resourceAppId": "00000002-0000-0ff1-ce00-000000000000",
     "resourceAccess": [
       {
         "id": "dc890d15-9560-4a4c-9b7f-a736ec74ec40",
         "type": "Role"
       }
     ]
   }

   ```
3. Sélectionnez **Save.**

   ![Image40 Pn](/images/Image40.png)
4. Sélectionnez **API permissions** sous **Manage**. Confirmez que la permission

   **full\_access\_as\_app** est bien listée.
5. Sélectionnez **Grant admin consent for org** et acceptez la boîte de dialogue de consentement.

![Image41 Pn](/images/Image41.png)

Pour ajouter la prise en charge des réunions Microsoft Teams à Workspace, poursuivez la configuration ci-dessous. Si vous ne souhaitez pas ajouter la prise en charge des réunions Microsoft Teams, passez à l'**étape 9.**

6. Sélectionnez **Add a permission**.
7. Sélectionnez la permission suivante **"Microsoft Graph> Calendars.ReadWrite"** et sélectionnez **Add**.
8. Accordez le consentement administrateur à cette permission.

![Image42 Pn](/images/Image42.png)

9. Sélectionnez **Certificates & Secrets** dans la navigation de gauche sous Manage.
10. Sélectionnez **New client secret**, entrez une courte description et sélectionnez **Add**.
11. Copiez la **Value** du secret client nouvellement ajouté et enregistrez-la. Vous en aurez besoin plus tard lors de la configuration du plugin de calendrier dans CMS.

    ![image.png](/images/image.png)

## Créer un utilisateur de compte de service

1. Connectez-vous à Office 365 en tant qu'administrateur.
2. Accédez à **Office 365 admin center > USERS > Active Users.**
3. Pour ajouter un nouvel utilisateur, sélectionnez l'icône "+". **La page de création d'un nouveau compte utilisateur** s'affiche.
4. Sur la page **de création d'un nouveau compte utilisateur**, complétez les informations requises.

   **A.** Entrez le prénom, le nom, le nom d'affichage, le nom d'utilisateur et votre domaine de messagerie.

   **B**. Sélectionnez **Type password** et entrez le mot de passe pour le compte de service.

   **C.** Décochez la case **Make this person change their password the next time they sign in**.

   **D.** Attribuez au moins une licence Exchange Online.

   **E.** Entrez l'adresse e-mail du destinataire à qui le mot de passe doit être envoyé. Sélectionnez **Create**.

   **F**. Sélectionnez **Close**.

## Gérer l'accès restreint (si nécessaire)

<Warning>
  Si vous avez ajouté une politique d'accès aux applications, vous devez d'abord inclure le compte de service dans le groupe de distribution à accès restreint.
</Warning>

Pour configurer une politique d'accès aux applications et limiter la portée des permissions d'application :

1. Connectez-vous à Exchange Online PowerShell. Pour plus de détails, consultez **Connect to Exchange Online PowerShell.**

2. Identifiez l'ID client de l'application et un groupe de sécurité à extension messagerie pour restreindre l'accès de l'application.

   **A.** Identifiez l'**application (client) ID** de l'application dans le **Azure app registration portal**.

   **B.** Créez un nouveau **groupe de sécurité à extension messagerie** ou utilisez un groupe existant et identifiez l'adresse e-mail du groupe.

   **C.** Assurez-vous d'ajouter votre compte de service et la ou les salles que vous souhaitez utiliser au **groupe de sécurité à extension messagerie.**

3. Créez une **politique d'accès aux applications.**

Exécutez la commande suivante en remplaçant les arguments **AppId** et **PolicyScopeGroupId**.

```
New-ApplicationAccessPolicy -AppId e7e4dbfc-046f-4074-9b3b-2ae8f144f59b - PolicyScopeGroupId mydistributiongroup@contoso.com -AccessRight RestrictAccess -Description "Restrict this app to members of distribution group."
```

4. Testez la politique d'accès aux applications nouvellement créée.

Exécutez la commande suivante en remplaçant l'argument **AppId** et **Identity** arguments.

```
New-DistributionGroup -Name "MyRoomList" -RoomList
Test-ApplicationAccessPolicy -Identity room01@contoso.com -AppId e7e4dbfc-046-4074-9b3b-2ae8f144f59b
```

La sortie de cette commande indique si l'application a accès à la boîte aux lettres room01.

<Info>
  Les modifications apportées aux politiques d'accès aux applications peuvent prendre jusqu'à 30 minutes pour prendre effet dans les appels API EWS.
</Info>

## Gérer la liste des salles (pour récupérer les salles à importer)

<Info>
  * Pour importer des salles dans Workspace, créez une liste de salles et ajoutez-y les salles que vous souhaitez importer. Sinon, vous devez ajouter les salles manuellement dans Workspace. Nous recommandons d'utiliser une liste de salles car c'est plus pratique que d'ajouter des salles manuellement.
  * Une liste de salles ne doit pas contenir plus de 100 salles. La requête pour une liste de salles retourne un maximum de 100 salles. Si vous prévoyez d'en avoir davantage, répartissez-les dans plusieurs listes de salles.
</Info>

1. Connectez-vous à Exchange Online PowerShell. Pour plus de détails, voir **Connectez-vous à Exchange Online PowerShell.**
2. Utilisez l'Exchange Management Shell pour créer une liste de salles.

   ```
   New-DistributionGroup -Name "MyRoomList" -RoomList
   ```
3. Utilisez l'Exchange Management Shell pour ajouter une salle à une liste de salles.

   ```
   Add-DistributionGroupMember -Identity " MyRoomList" -Member room
   ```

Add-DistributionGroupMember -Identity " MyRoomList" -Member [room01@contoso.com](mailto:room01@contoso.com)

4. Pour vérifier que vous avez créé la liste de salles avec succès, exécutez la commande suivante pour voir si la liste existe.

```
Get-DistributionGroup -Identity "Room list name"
```

Après avoir configuré l'enregistrement de l'application et créé le compte de service, renseignez la configuration du plugin Calendrier dans le portail d'administration CMS.

**Exchange Server**: [http://outlook.office365.com](http://outlook.office365.com) / example

**Application ID :** L'ID d'application depuis Azure

**Tenant ID**: L'ID de locataire du répertoire depuis Azure

**Client secret Key**: La clé secrète client depuis Azure.

**Default service account**: Le compte de service par défaut du répertoire Azure pour récupérer l'accès.

**Impersonation**: Décrit ci-dessous

**Room list address**: L'URL SMTP de la liste de salles que vous avez configurée. Cela vous permettra d'importer des salles dans Workspace.

**Allow online meeting creation :** Cette option doit être activée pour prendre en charge les réunions Microsoft Teams.

Vous pouvez également sélectionner l'option de réunion Teams **par défaut** lorsque les utilisateurs créent des événements dans Workspace :

1. Accédez à **CMS Administration**.
2. Ouvrez **Workspace application settings**.
3. Sélectionnez **Enable online meeting creation by default** et cliquez sur **Save**.

### Impersonation

Il existe trois modes de fonctionnement, décrits ci-dessous. Définissez le mode de fonctionnement en fonction des résultats souhaités et des règles de sécurité de votre entreprise :

![Image50 Pn](/images/Image50.png)

### #1. Impersonation = Full access

En utilisant ce type d'usurpation d'identité Full Access, la fonction de réservation aura le comportement suivant :

### Réservation depuis Outlook

La réservation sera effectuée depuis le compte utilisateur avec le choix de la salle et des invités.

Cette réservation peut être modifiée et supprimée depuis Outlook et Workspace.

La modification et la suppression de la réservation sur la tablette affecteront à la fois le calendrier de l'utilisateur et celui de la ressource.

### Réservation depuis Workspace

La réservation sera effectuée depuis le compte utilisateur avec le choix de la salle et des invités.

Cette réservation peut être modifiée et supprimée depuis Workspace et Outlook.

La modification et la suppression de la réservation sur la tablette affecteront à la fois le calendrier de l'utilisateur et celui de la ressource.

### Réservation depuis une tablette

La réservation sera effectuée depuis le compte de service qui usurpera l'identité de l'utilisateur connecté.

Le propriétaire / organisateur de la réunion sera l'utilisateur connecté.

Cette réservation peut être modifiée et supprimée depuis la tablette et affectera le calendrier de l'utilisateur et de la ressource.

La modification, la suppression ou l'ajout de participants peut être effectué via le calendrier de l'utilisateur (qui est propriétaire de cette réunion).

### **#2. Impersonation = Resources only**

Cette option nécessite que le compte de service ait le droit d'usurper l'identité de toutes les ressources importées dans PADS4 CMS. Pour gérer cela, accordez le rôle **"ApplicationImpersonation"** à l'utilisateur du compte de service en suivant ce script PowerShell :

```powershell
New-ManagementScope -Name "CrystalResourceMailboxes" - RecipientRestrictionFilter {RecipientTypeDetails -eq "RoomMailbox"}
```

```powershell
New-ManagementRoleAssignment -name "CrystalResourceImpersonation" -Role ApplicationImpersonation -User "serviceAccount" -CustomRecipientWriteScope "CrystalResourceMailboxes"
```

![Image52 Pn](/images/Image52.png)

En utilisant ce type d' **"Resources Only"** usurpation d'identité, la fonction de réservation aura le comportement suivant :

### Réservation depuis Outlook

La réservation sera effectuée depuis le compte utilisateur avec le choix de la salle et des invités.

Cette réservation peut être modifiée et supprimée depuis Outlook et Workspace.

La modification et la suppression de la réservation sur la tablette n'affecteront que le calendrier de la ressource.

### Réservation depuis Workspace

La réservation sera effectuée depuis le compte utilisateur avec le choix de la salle et des invités.

Cette réservation peut être modifiée et supprimée depuis Workspace et Outlook.

La modification et la suppression de la réservation sur la tablette n'affecteront que le calendrier de la ressource.

### Réservation depuis une tablette

La réservation sera effectuée depuis le compte de service qui usurpera l'identité de la ressource.

Le propriétaire / organisateur de la réunion sera la ressource et l'utilisateur connecté sera ajouté en tant que participant.

Cette réservation peut être modifiée et supprimée depuis la tablette et affectera le calendrier de l'utilisateur et de la ressource.

La modification, la suppression ou l'ajout de participants peut être effectué via le calendrier de la ressource (qui est propriétaire de cette réunion).

### #3. Impersonation = None

En utilisant ce type d'usurpation d'identité "None", la fonction de réservation aura le comportement suivant :

### Réservation depuis Outlook

La réservation sera effectuée depuis le compte utilisateur avec le choix de la salle et des invités.

Cette réservation peut être modifiée et supprimée depuis Outlook.

La modification et la suppression de la réservation sur tablette n'affecteront que le calendrier des ressources.

### Réservation depuis une tablette

La réservation sera effectuée depuis le compte de service qui usurpera l'identité de la ressource.

Le propriétaire / organisateur de la réunion sera la ressource et l'utilisateur connecté sera ajouté en tant que participant.

Cette réservation peut être modifiée et supprimée depuis la tablette et affectera le calendrier de l'utilisateur et de la ressource.

La modification, la suppression ou l'ajout de participants peut être effectué via le calendrier des ressources (qui est propriétaire de cette réunion).

### Rechercher une boîte aux lettres

Cette fonction d'activation dans Microsoft Exchange vous permettra d'importer automatiquement depuis une liste de diffusion ou vos ressources Exchange.

Si cette fonction n'est pas activée, vous devez créer ces salles manuellement. Cependant, une fois les salles créées, le fonctionnement de l'application Workspace restera strictement identique entre une salle importée et une salle créée.

### Délégation

Ce prérequis sera nécessaire si l'emprunt d'identité n'est pas autorisé.

Cette délégation permettra au compte de service de lire le calendrier des ressources.

### Dépannage

Si vous avez suivi les étapes ci-dessus et que vous ne parvenez toujours pas à importer ou à réserver des salles dans Workspace, vérifiez la configuration du plugin CMS Calendar par rapport à la configuration de votre tenant.

Étant donné qu'il s'agit d'une configuration assez complexe, nous constatons que les erreurs de configuration sont la principale cause de dysfonctionnement du système.

Si cela ne fonctionne toujours pas, ouvrez un ticket dans le PADS4 Partner Portal et envoyez-nous le **nds.services.crystal.pads** fichier journal dans le dossier Logs de PADS4.
