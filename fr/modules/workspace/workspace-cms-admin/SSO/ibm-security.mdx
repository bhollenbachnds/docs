<Warning>
  À partir de PADS4 2025.2, cette fonctionnalité fait partie de PADS4 CTRL Center. Pour plus d'informations, voir CTRL Center > Administration > Identity.
</Warning>

Ce guide vous explique comment configurer **SAML 2.0 Single Sign-On (SSO)** en utilisant **IBM Security Verify** comme fournisseur d'identité (IdP) pour **PADS4 Workspace**.

***

## Prérequis

Assurez-vous que les éléments suivants sont prêts :

* Accès à [IBM Security Verify Console](https://www.ibm.com/security/identity-access-management/verify)
* Certificat de signature (.pem ou .cer) depuis IBM Verify
* Certificat PFX avec clé privée pour PADS4 (.pfx)
* URL des métadonnées de fédération (facultatif si importé manuellement)
* URL du serveur PADS4 (ex. : `https://pads4serverurl/crystal/domainone`)

***

## Étape 1 : IBM Security Verify – Configuration de l'application

### Accédez à :

**Directory > Applications > Add Application > Custom Application**

### Sous le **Sign-on** tab:

| Champ                              | Valeur                                                |
| ---------------------------------- | ----------------------------------------------------- |
| **Méthode de connexion**           | `SAML 2.0`                                            |
| **Provider ID**                    | `https://pads4serverurl/crystal/domainone/Saml2`      |
| **Assertion Consumer Service URL** | `https://dpads4serverurl/crystal/domainone/Saml2/ACS` |
| **Service Provider SSO URL**       | `https://pads4serverurl/crystal/domainone/Saml2/ACS`  |
| **SessionNotOnOrAfter**            | `7200` (2 heures)                                     |

<Warning>
  Ne PAS sélectionner « Use Identity provider-initiated single sign-on »
</Warning>

***

### Signature Settings

| Champ                                  | Valeur                              |
| -------------------------------------- | ----------------------------------- |
| **Sign authentication response**       | Activé                              |
| **Signature Algorithm**                | RSA-SHA256                          |
| **Signing Certificate**                | Choose Default personal certificate |
| **Validate SAML request signature**    | Activé                              |
| **Validate logout request signature**  | Activé                              |
| **Validate logout response signature** | Activé                              |

Laisser **Service Provider Certificate** et **Encryption Options** vide sauf si le chiffrement est requis par votre organisation.

***

### SAML Subject

| Champ               | Valeur               |
| ------------------- | -------------------- |
| **NameID Format**   | `Unspecified`        |
| **Name Identifier** | `preferred_username` |

***

### Attribute Mapping

Enable: ☑ **Send all known user attributes in the SAML assertion**

| **Attribute name**                                                                                                                        | **Attribute Name format (URN)**                            | **Format** | **Attribute source** |
| :---------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------- | :--------- | :------------------- |
| [**http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress**](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/email)     | `urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified`  | email      | `email`              |
| [**http://schemas.xmlsoap.org/ws/2005/05/identity/claims/**](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/familyname)**surname** | `urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified ` | text       | `family_name`        |
| [**http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname**](http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname)    | `urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified ` | text       | `given_name`         |
| [**http://schemas.microsoft.com/identity/claims/**](http://schemas.microsoft.com/identity/claims/uid)**objectidentifier**                 | `urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified ` | text       | `uid`                |
| [**http://schemas.xmlsoap.org/claims/group**](http://schemas.xmlsoap.org/claims/group)                                                    | `urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified ` | text       | `groupIDs`           |

> Ces attributs seront mappés dans PADS4 pour attribuer des rôles/groupes.

***

### Access Policy

* Définir sur : ☑ **Use default policy**
* Autoriser depuis : `All devices`

***

## Étape 2 : PADS4 Workspace – Configuration SSO

Dans le **PADS4 Administration Portal**, configurez le plugin SSO comme suit :

| Champ                                        | Valeur                                                        |
| -------------------------------------------- | ------------------------------------------------------------- |
| **Type**                                     | `Azure AD` (ou `Custom` / `SAML` selon le cas)                |
| **Federation Service Identifier**            | `https://pads4.verify.ibm.com/saml/sps/saml20ip/saml20`       |
| **SAML SSO URL**                             | `https://pads4.verify.ibm.com/saml/sps/saml20ip/saml20/login` |
| **Federation Metadata URL** (facultatif)     | `https://pads4.verify.ibm.com/v1.0/saml/federations/saml2`    |
| **Certificate of Federation Server**         | Téléverser le **certificat de signature IBM Verify (.cer)**   |
| **URL of Relying Party**                     | `https://pads4serverurl/crystal/domainone`                    |
| **Relying Party Signing Certificate (.pfx)** | Téléverser votre `.pfx` fichier avec clé privée               |
| **Private Key Password**                     | Saisir le mot de passe pour `.pfx`                            |

***

## Étape 3 : Mappage des groupes dans PADS4

Accéder à la **Relation Table** section du plugin SSO et mapper les `groupIDs` entrants d'IBM vers les profils PADS4 :

| Active Directory Group ID | Profil         |
| ------------------------- | -------------- |
| `admin`                   | Administration |
| `admin`                   | Défaut         |
| `developer`               | Défaut         |

***

## Vérifications finales

* Tester la connexion via PADS4 en utilisant un utilisateur vérifié par IBM.
* S'assurer que les claims sont correctement reçus et analysés dans PADS4.
* Ajuster le mappage des attributs ou les règles de claims si les utilisateurs ne sont pas correctement assignés.
