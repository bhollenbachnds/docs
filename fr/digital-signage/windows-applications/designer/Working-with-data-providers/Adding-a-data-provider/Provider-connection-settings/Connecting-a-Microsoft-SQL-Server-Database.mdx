Le **Microsoft SQL Server** dans **PADS4** vous permet de vous connecter à une **base de données SQL Server**, de récupérer des données et de les utiliser dans votre présentation.

***

### **Étapes pour ajouter ou modifier une connexion Microsoft SQL Server**

#### **1. Démarrer l'Assistant Fournisseur de données**

* Ouvrez **PADS4** et accédez à l'**Assistant Fournisseur de données**.
* Sélectionnez **Microsoft SQL Server** comme **type de fournisseur**.
* Cliquez sur **Suivant** pour continuer.

#### **2. Spécifier les paramètres de connexion SQL Server**

* Entrez le **Nom du serveur SQL** :
  * Saisir manuellement le **nom du serveur**.
  * Cliquer sur le **bouton déroulant** pour rechercher et sélectionner un serveur disponible sur votre réseau.
* Dans la **Logon to the Server** section, sélectionner l'une des méthodes d'authentification :
  * **Windows Authentication** *(utilise les informations d'identification de l'utilisateur actuel)*.
  * **SQL Server Authentication** *(nécessite un nom d'utilisateur et un mot de passe)*.
* Cliquer sur **Next** pour continuer.

#### **3. Sélectionner la base de données et la source de données**

* Sélectionner la **base de données** dans la liste déroulante.

* Sélectionner la **source de données**:
  * **Tables** – Récupérer les données d'une table spécifique.
  * **Views** – Utiliser une vue SQL Server prédéfinie.
  * **Stored Procedures** – Exécuter une procédure stockée.
  * **SQL Statement** – Saisir manuellement une requête SQL personnalisée.

* Si vous utilisez **SQL Statement**, s'assurer qu'elle est optimisée pour les performances.

* Cliquer sur **Next** pour continuer.

#### **4. Finaliser la configuration**

* **Vérifier** les paramètres de connexion.
* Cliquer sur **Finish** pour enregistrer le fournisseur de données.

***

### **Remarques importantes**

* **SQL Server Authentication**:
  * Si vous utilisez **Windows Authentication**, s'assurer que le **service PADS4** dispose des **autorisations appropriées**.
  * Si vous utilisez **SQL Server Authentication**, utiliser un **nom d'utilisateur et mot de passe sécurisés**.
* **Optimisation des requêtes**:
  * L'utilisation de **Views** ou de **Stored Procedures** est recommandée pour plus d'efficacité.
  * Éviter les **requêtes SQL complexes** dans les **SQL Statements** dans la mesure du possible.
* **Considérations de performance**:
  * **SQL Server est optimisé** pour traiter les requêtes en interne.
  * L'utilisation d'un **PADS4 Data Server** peut ne pas apporter d'avantages supplémentaires.

Cette configuration permet à **PADS4** de récupérer efficacement les **données SQL Server en temps réel**, ce qui le rend utile pour les **présentations dynamiques, tableaux de bord et automatisation**.
