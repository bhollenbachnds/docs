If you want to upgrade to PADS4 2025.1, your current PADS4 version must be at least PADS4 2022.3. That means you need to have PADS4 2022.3 installed and running before you update to 2025.1.

Versions 2022.2 and lower don't automatically update to 2025.1. You need to perform an intermediate upgrade to PADS4 2022.3 first.

Release notes for PADS4 Version 2025.1 [can be found here.](https://www.netdisplaysystems.com/downloads/ForwardLinks/PADS4relnotes.pdf)

<Warning>
  User Accounts and Security Update

  As of version 2025.1, the default users User1 and Administrator have been removed to enhance security. During setup, you must create a new user account. You create this user with the Root user, whose password you define during the installation process.
</Warning>

In our latest release, 2025.1, we introduce our new user management system.

<Warning>
  This fundamental change moves the User Management settings from the System Management application to the PADS4 Web Portal.

  Read the following articles to prepare yourself for this change.

  [Account creation](https://docs.pads4.com/ctrl-centre/account-creation) & [Roles](https://docs.pads4.com/ctrl-centre/administration/user-management/Roles)
</Warning>

### HSTS

From 2023.2 onwards, the PADS4 configuration wizard includes a new security feature called HSTS.

<img
  className="block"
  src="/images/hsts.png"
  alt="HSTS"
/>

The HSTS toggle enables the HTTP Strict Transport Security header on all http requests. This header instructs smart devices (PADS4 HTML5 Viewers, PADS4 CTRL Center, PADS4 CMS (legacy)) to use the HTTPS protocol instead of HTTP. For example, if you connect to [http://pads4server.com/](http://pads4server.com/), all connections on that web app are upgraded to HTTPS.

<Warning>
  Important: You need to have HTTPS enabled and have a valid certificate. If the certificate is not valid, any connection from HTTP or HTTPS doesn't work. This means that PADS4 devices on HTTP no longer connect to the server, and the connection is lost. Always check that your certificate is valid and working on HTTPS before you enable HSTS.
</Warning>
